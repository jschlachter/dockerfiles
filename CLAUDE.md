## Repository Purpose

A personal collection of container configurations for self-hosted services. Two deployment patterns are used:

- **Docker Compose** (`docker-compose.yml`): kafka, mssql, nginx-proxy-manager, plex, registry-mirror, seq
- **Podman Quadlets** (`.container`, `.pod`, `.volume`, `.network` files): authentik, rabbitmq, wikijs

## Podman Quadlet Architecture

Quadlets are systemd unit files generated by Podman to manage containers as system services. Multi-container services (authentik, wikijs) use a pod to share a network namespace, allowing inter-container communication via `localhost`. Dependencies between containers are expressed with systemd `After=` and `Requires=` directives.

Quadlet files live in `~/.config/containers/systemd/` for user services. The `%h` token in quadlet files expands to the user's home directory.

## Deploying / Managing Services

### Docker Compose services
```bash
cd <service-directory>
docker-compose up -d
docker-compose logs -f
docker-compose down
```

### Podman Quadlet services
```bash
# Copy files and activate
cp <service>/*.{container,pod,volume,network} ~/.config/containers/systemd/
systemctl --user daemon-reload

# Start/stop/status (pod name = service name)
systemctl --user start <service>.service
systemctl --user stop <service>.service
systemctl --user status <service>.service

# Logs
journalctl --user -u <service>.service -f
```

Use `enable-service.sh <service-name>` as a shortcut: it runs `daemon-reload`, enables, and shows status.

## Configuration

- `.env` files are gitignored — create them locally before starting services
- Quadlet `EnvironmentFile=` paths are relative to the quadlet file location
- Volume host paths use `%h` (home dir); update if you want a different location
- Each service directory contains a README with required env vars and port mappings
